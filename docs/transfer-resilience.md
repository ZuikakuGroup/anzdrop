# ファイル転送のE2E・耐障害性テスト

開発者向けの実行手順。まず軽量テストを実行し、転送処理を変更した場合は障害検証を追加する。結果と未検証の範囲は末尾に記録する。

## 通常の開発とPR

```sh
npx playwright install chromium firefox webkit
npm test -- tests/test/sharingFiles.test.ts tests/scripts/local-worker-config.test.ts tests/components/upload/uploadForm.test.ts
npm run test:sharing
E2E_PROJECT=firefox npm run test:sharing
E2E_PROJECT=webkit npm run test:sharing
```

`test:sharing` は既存の `test:astro-hono` でAstro・Hono・workerdをローカル起動し、1ワーカーで共有スイートを実行する。固定ポートを使うため、複数の実行を同時起動しない。ブラウザごとの互換性を調べる場合も順番に実行する。

基本テストは通常送信、保護パスワードの誤入力と再試行、複数ファイルのZIP、テキスト・PNG・1MiBバイナリ、日本語・空白を含む名前、375px幅、空ファイル拒否を確認する。送信元と受信先は独立したBrowserContextで、Cookieやストレージを共有しない。

保存したファイルは送信前後のSHA-256とサイズを比較する。SHA-256はストリームで計算し、大容量ファイル全体をテストドライバのメモリへ読み込まない。ZIPは小容量テストのみ展開し、各エントリのハッシュを比較する。

## 障害と同時利用を検証する

```sh
E2E_RESILIENCE=1 npm run test:sharing
E2E_EXTENDED=1 npm run test:sharing
E2E_PROJECT=firefox E2E_RESILIENCE=1 E2E_EXTENDED=1 npm run test:sharing
E2E_CROSS_ENGINE=1 npm run test:sharing -- --grep @sharing-cross-engine
```

| 指定 | 検証内容 |
| --- | --- |
| `E2E_RESILIENCE=1` | 送信中の通信切断・ブラウザの通信タイムアウト・503・通信中断と再試行、送信中の再読み込み、不正な鍵、存在しない共有、期限切れ、R2の欠落、同時送信・同時受信 |
| `E2E_EXTENDED=1` | 16MiB＋1Bの3パート転送・10MiBのBlob保存、16MiB＋1Bの保存キャンセルと再試行、ダウンロード通信失敗・暗号文破損・空レスポンス |
| `E2E_CROSS_ENGINE=1` | Chromium送信・別プロセスのFirefox受信。両エンジンのインストールが必要 |

通信切断のケースは16MiB＋1Bを使い、先頭パートの保存後に後続を失敗させる。再試行で先頭から正常に転送されることもハッシュで確認する。

送信障害は実際の `/api/upload/start` 成功後、暗号文の `/api/upload/chunk` リクエストだけに注入する。失敗時にcomplete APIが呼ばれず、URLコピーも出現しないことを確認してから、障害を解除して再送・ダウンロードのハッシュ一致まで検証する。再読み込み時に自動再開は期待しない。再選択による新しい送信を確認する。

タイムアウトの試験はPlaywrightの `route.abort('timedout')` を使う。無応答のAPIにアプリ独自の待機上限を追加したわけではない。送信中のキャンセルボタンは現仕様にないため、通信レベルの中断とページ離脱を検証し、新しいキャンセル・再開機能は実装しない。

期限切れとR2欠落の試験では、そのテストで作った共有だけをローカルD1で更新する。期限を過去へ変更するか、オブジェクトの参照先を存在しない合成キーへ変更し、実APIの410・404と画面の挙動を確認する。テスト専用APIは追加しない。

ダウンロードの通信障害は、8MiB以降のRangeリクエストを失敗させる。最初のウィンドウは実通信で取得する。Blob経路で不完全ファイルを保存しないことと、障害を解除した再試行でのハッシュ一致を確認する。保存キャンセルは実際に転送可能ストリームとService Workerが使えるブラウザだけが対象で、Blob経路の挙動と混同しない。

## 大容量はサイズを明示して実行する

```sh
E2E_LARGE_MIB=10 npm run test:sharing -- --grep @sharing-size
E2E_LARGE_MIB=100 npm run test:sharing -- --grep @sharing-size
# 十分な空き容量・メモリ・時間がある場合だけ実行する
E2E_LARGE_MIB=1024 npm run test:sharing -- --grep @sharing-size
```

指定可能な値は1・10・100・1024 MiB。アプリの無料プランの1ファイル上限は5GiBだが、テストの上限は1GiBに限定する。1GiBは最大15分、それ以外のサイズ指定は最大5分。基準サイズと暗号化チャンクの境界は異なるため、別途マルチパート試験も残す。Blobへフォールバックするブラウザではアプリ側のメモリ使用量が増える。OSの空き容量やブラウザのメモリを確認して実行する。

共有テストは専用の3ブラウザWorkflowへ集約し、CIのpublic-pagesジョブでは重複実行しない。PRでは基本テストのみ、夜間は基本と `E2E_RESILIENCE`、手動Workflowでは基本・耐障害性・拡張を実行する。100MiB・1GiBは夜間にも自動実行しない。Workflowの `size_mib` を明示した場合だけChromiumでサイズ試験を追加し、他2ブラウザで同じ大容量を重複転送しない。

## ローカル資源とテストデータ

サーバーに新しい情報を保存する設計変更はない。R2は既存どおり暗号文、D1は共有・暗号化済みファイル名・転送セッション等の既存レコードに使う。テストは既存スキーマをローカルに再現する。

- API用設定からCloudflare account IDと公開ルートを外し、D1・R2を `remote: false` と合成リソース名へ固定する。
- ルートの `.dev.vars` は読み込まず、Turnstileは公式テストキー、認証・分析はローカル専用の合成鍵を使う。
- 実行ごとに `tmp/astro-hono-state.XXXXXX` を作り、終了時にそのディレクトリだけを削除する。開始したプロセスグループも終了する。SIGKILL・マシン停止では終了処理を保証できない。
- ファイルは実行専用の `tmp/astro-hono-state.XXXXXX/fixtures/<testId>/inputs` と `saved` に生成し、失敗時もafterEachでその2ディレクトリだけを削除する。テストが中断してafterEachへ到達しなくても、runnerの終了処理で実行専用領域ごと削除する。Playwrightのブラウザダウンロード領域もContext終了時に破棄する。
- 送信URL・ヘッダー・本文に合成の平文マーカー・名前・パスワード・実際の復号鍵が出ていないか、既存のPrivacyWatchで監視する。検査結果には値を添付しない。

失敗トレースには合成ファイルの内容・合成鍵が含まれる場合がある。実データを使わない。CIの既存失敗成果物は7日保持。ログとトレースは原因調査用として残し、テスト用D1・R2や入力・保存ファイルは残さない。

## 仕様上の制約と修正

APIは `fileSize > 0` を要求し、空ファイル転送をサポートしていない。従来の画面は空ファイルをキューへ入れ、混在バッチの途中でAPIエラーになっていた。選択・ドロップの共通入口で空ファイルを含む選択全体を拒否するよう修正した。先行暗号化やアップロードを始めず、既に選択済みの別ファイルは保持する。API・暗号形式の仕様は変えない。

実機iOS・Android、OSの保存ダイアログ、実ネットワークの帯域・パケット損失、Cloudflare本番エッジや署名付きR2直接転送は、このローカルproxyモードの試験では検証できない。WebKitの成功をiOS Safariの実機確認とは扱わない。[Safari確認表](safari-file-sharing-checklist.md)も参照する。

### PR #297のLinux WebKit CI修正

Linux WebKitのService Worker経由保存では、`日本語 の テキスト.txt` が `日本語_の_テキスト.txt` として提案され、ファイル名の完全一致テストが失敗した。該当エンジン・OS・保存経路に限り、ASCII空白から `_` への変換も許容する。日本語部分や拡張子の欠落は許容しない。元の空白を保持した `filename*` ヘッダーをunitテストで確認し、保存内容のSHA-256照合も維持する。アプリの保存名や暗号化処理は変更していない。

修正後はmacOS上のWebKit基本E2E 5件が37.6秒、関連unit 12件が267msで成功した。対象ファイルのLint・TypeScriptも成功し、独立レビューで修正必須の指摘はなかった。Linux固有の変換は既存CIの失敗ログで確認しており、修正後のLinux分岐の実行結果は更新後のCIで確認する。
